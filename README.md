# NH Fitness

One Flutter codebase for the gym's **website, Android app and iOS app**, backed
by one Firebase project (`nh-fitness-8a972`) on the free Spark plan.

`PRD.md` in this folder is the single source of truth. Every file here points
back to the section of it that asked for the behaviour.

## What Phase 1 does

- Visitors see the gym, the plans and the live prices without logging in.
- A member registers, picks a plan, pays by **UPI** (QR + 12-digit reference
  number) or chooses **Pay at gym**, and submits a request.
- The owner approves the payment in the admin panel; the membership activates
  and the online classes unlock.
- Prices, plans, contact details, classes and announcements are all editable
  from the admin panel — no new app release needed.

There are **no Cloud Functions and no Firebase Storage** (PRD section 3), which
is why payment approval is a human step.

## First-time setup

### 1. Connect Firebase

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=nh-fitness-8a972
```

This overwrites `lib/firebase_options.dart`, which currently holds placeholder
values — the app shows a setup screen with these instructions until it is run.

Then, in the Firebase Console (PRD section 4):

| Step | Where | What |
|---|---|---|
| 1 | Authentication → Sign-in method | Enable **Email/Password** and **Google** |
| 2 | Authentication → Settings → Authorized domains | Add the website domain (`localhost` is already there) |
| 3 | Firestore Database | Create in production mode, location **`asia-south1` (Mumbai)** — this cannot be changed later |
| 4 | Firestore → Rules | Paste `firestore.rules` and publish |
| 5 | Firestore → Indexes | Create the indexes in `firestore.indexes.json` |
| 6 | Project settings | Add the Web, Android (`com.nhfitness.app`) and iOS (`com.nhfitness.app`) apps, plus the debug and release **SHA-1** for Google login on Android |

With the Firebase CLI installed, steps 4 and 5 are one command:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

### 2. Seed the data

Log in to the app, then open **Admin → Plans and prices → Create default
plans**. That writes the four plans from PRD section 8.2. Fill in the real
values under **Admin → Settings** (UPI ID, address, timings, phone, email,
Instagram).

### 3. Make yourself an admin

There is deliberately no sign-up path for this (PRD section 2):

1. Log in to the app once.
2. Firebase Console → Authentication → copy your **User UID**.
3. Firestore → create document `admins/{your UID}` with
   `name` (string) and `addedAt` (timestamp).

## Run it

```bash
flutter pub get
flutter run -d chrome        # website
flutter run -d <device-id>   # Android or iOS
```

## Test it

```bash
flutter analyze              # must be clean
flutter test                 # unit + widget tests

cd rules-test && npm install && npm test   # Firestore rules, needs Node + Java
```

## Build and publish the website

```bash
flutter build web --release
```

Upload **everything inside `build/web/`** to `public_html/`. `web/.htaccess` is
copied into the build automatically and is what makes path URLs like `/plans`
survive a refresh on Apache/cPanel hosting (PRD section 12). Make sure HTTPS is
on, and add the domain under Firebase Auth → Authorized domains.

## Build the Android app

```bash
flutter build appbundle --release
```

Add a real signing config in `android/app/build.gradle.kts` first — the release
build is currently signed with the debug key so that `flutter run --release`
works (PRD milestone M9).

## How the code is laid out

```
lib/
  main.dart                  Firebase init, then NHApp
  firebase_options.dart      generated by flutterfire (placeholder until then)
  app/
    app.dart                 MaterialApp.router, splash, Firebase setup screen
    router.dart              go_router table + the guards from PRD section 6
    theme.dart               colours and type from PRD section 5
  core/
    assets.dart              every image URL, in one place (PRD section 5.6)
    format.dart              ₹ formatting and all Asia/Kolkata date maths
    motion.dart              the animations in PRD section 5.4
    responsive.dart          the breakpoints in PRD section 5.5
    validators.dart          field rules (UTR, phone, password)
    widgets/                 buttons, cards, pills, logo, shell, states
  data/
    models/                  one per Firestore collection
    repositories/            the only code that talks to Firestore
  features/
    home/ explore/ plans/ checkout/ auth/ account/ classes/
    announcements/ legal/ misc/ admin/
  l10n/app_en.arb            every string in the app (PRD section 13)
test/                        unit + widget tests
rules-test/                  Firestore rules tests (Firebase Emulator)
firestore.rules              the security boundary (PRD section 9)
firestore.indexes.json       composite indexes (PRD section 10)
```

Two rules keep the codebase honest:

- **Only repositories touch Firestore.** Screens read providers.
- **Only `app_en.arb` holds user-facing text.** Adding `app_hi.arb` is all it
  takes to offer Hindi later.

## Things to know

- **Money** is stored as whole rupees (`int`). **Calendar days** (`startDate`,
  `endDate`) are stored at 00:00 Asia/Kolkata. Both conventions come from
  PRD section 8 and `core/format.dart` is the only place that implements them.
- **The security rules are the security boundary.** The Firebase web config in
  `firebase_options.dart` is not a secret; a service-account key would be, and
  must never be committed.
- **Prices are never hard-coded** (PRD HOME-1). `Plan.defaults` and
  `AppSettings.defaults` exist only to seed a fresh project and to keep the UI
  rendering if a document is missing a field.
- **Lists are paginated 20 at a time** and only two things stream in real time —
  the admin's pending queue and a member's own requests — to stay inside the
  Spark plan's daily read cap (PRD section 13).
